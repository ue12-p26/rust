# Application folders

:::{warning} To review
:class: readiness-toreview

:::

On each operating system, an application has *dedicated spaces* to store:

- Cache files.
- Configuration files.
- Application's data.

It is of utmost importance for an application to respect the user's storage
space and write files only inside dedicated folders. The
[ProjectDirs](https://docs.rs/directories/latest/directories/struct.ProjectDirs.html)
structure from the
[directories](https://docs.rs/directories/latest/directories/index.html)
crate provides methods (see {numref}`tab-project-dir-methods`) to get the
right standard paths for application folders, depending on the operating
system.

Once initialized, a new instance of `ProjectDirs` will give us the paths
to all standard applications folders: cache, config, data, preference, ...

:::{list-table} Some methods of ProjectDirs
:name: tab-project-dir-methods
:header-rows: 1
:align: center

* - Method
  - Description
* - `from(qual, org, app)`
  - Creates a `ProjectDirs` instance from a *qualifier* string, an
    *organization* name and an *application* name.
* - `cache_dir()`
  - Returns the path to the cache folder.
:::

## Initializing

```{code-cell} rust
:tags: [remove-cell]

:dep directories = "5"
```

To initialize a new `ProjectDirs` instance we use the `from()` static
method that takes three arguments:

1. `qualifier`: the reverse of the domain name of the application,
   without the organization name and the application name. For instance
   if the application is `foo`, the organization `whatever` ad the full
   domain name is `foo.whatever.openprojects.org`, then the qualifier is
   `org.openprojects`. *An empty string is accepted*.
2. `organization`: The name of the organization that develops the
   application. *An empty string is accepted*.
3. `application`: The name of the application.

Example:

```{code-cell} rust
:class: seq-start badges border

use directories::ProjectDirs;

let prj = ProjectDirs::from("org.openprojects", "whatever", "foo").unwrap();
```

## Cache folder

The *cache* folder is used by applications to store *cache* files.
*Cache* files are a type of temporary files used to store intermediate
data, so it can be *reused* on every run and avoid to *re-fetch* or
*recompute* it.

Here is how to get the application's cache folder:

```{code-cell} rust
:class: seq-cont badges border

prj.cache_dir()
```

## Configuration folder

The *configuration* folder is used by applications to store their
configuration options. On *Windows*, we distinguish the `local` folder
that is only stored locally on the computer, from the standard folder
that synchronized with a cloud system.

To get the standard folder:

```{code-cell} rust
:class: seq-cont badges border

prj.config_dir()
```

The local folder is the same as the standard folder for *UNIX-like*
systems:

```{code-cell} rust
:class: seq-cont badges border

prj.config_local_dir()
```

## Data folder

The *data* folder is used by applications to access their data files
that came installed during their initial installation process. On
*Windows*, we distinguish the `local` folder that is only stored locally
on the computer, from the standard folder that synchronized with a cloud
system.

To get the standard folder:

```{code-cell} rust
:class: seq-cont badges border

prj.data_dir()
```

The local folder is the same as the standard folder for *UNIX-like*
systems:

```{code-cell} rust
:class: seq-cont badges border

prj.data_local_dir()
```

## Preference folder

*UNIX-like* systems, except *macOS*, make *no difference* between the
*preference* folder and the *configuration* folder. The *preference*
folder is used to store also configuration information, but more
related to user choices about *look & feel*.

Here is the *preference* folder on the operating system used to build
this book:

```{code-cell} rust
:class: seq-cont badges border

prj.preference_dir()
```

## Runtime folder

The *runtime* folder is used to store *transient* files, like named
sockets and named pipes, that are *deleted* when the application
*terminates*. It is only used on *Linux* platforms.

Here is how to get the *runtime* folder:

```{code-cell} rust
:class: seq-cont badges border

prj.runtime_dir()
```

## State folder

The *state* folder is used to store data generated by the application,
and that needs to be saved between two executions. It is only used on
*Linux* platforms.

Here is how to get the *state* folder:

```{code-cell} rust
:class: seq-stop badges border

prj.state_dir()
```
